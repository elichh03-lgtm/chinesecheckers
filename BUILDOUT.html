02 Game Engine Weeks 1–3

The game engine lives in packages/game-engine — pure TypeScript, zero dependencies, 100% unit tested. Everything that touches game rules goes here. This is the most critical piece of the entire project; bugs here corrupt game state permanently.

Board Model
Axial hex coordinate system
Define Hex { q, r } type. Implement 6-direction neighbor lookup. Hex distance function. hexToString / stringToHex helpers.
2h
Critical
BOARD_POSITIONS Set (121 holes)
Hardcode all valid axial coordinates for the star board. Verify count is exactly 121. Write test.
3h
Critical
HOME_TRIANGLES & TARGET_TRIANGLES
10 holes per player, for all 6 starting positions. TARGET = opposite HOME. Config for 2P, 3P, 4P, 6P layouts.
2h
Critical
Pixel ↔ Axial conversion functions
Used by the Canvas renderer. hexToPixel(hex, size) and pixelToHex(x, y, size). Flat-top orientation.
2h
Initial board state factory
createInitialBoard(playerCount, playerIds) → places all marbles in home triangles. Returns full GameState.
1h
Move Validation
Step move validator
Assert marble belongs to current player. Assert destination is empty neighbor. Return ValidMove | InvalidMove.
1h
Critical
Single hop validator
Midpoint must exist on board and be occupied. Landing must be empty. No capturing.
2h
Critical
Chain hop validator
Validate full hop path. No revisiting holes. Can change direction each hop. Can stop at any point mid-chain.
3h
Critical
Complete move validator (entry point)
Combines all validators. Takes (state, playerId, move) → ValidationResult with typed error reasons.
1h
Move Generation
Valid destination generator (BFS)
getValidDestinations(state, from). Returns all reachable holes for a marble via step or any hop chain. Used for UI highlighting.
3h
Critical
All valid moves generator
getAllValidMoves(state, playerId). Used for auto-move on timeout and future AI. Returns array of Move.
2h
State Management
Apply move function
applyMove(state, move) → new immutable GameState. Advances turn index. Increments move counter.
1h
Win condition checker
checkWin(state, playerId). All 10 marbles in target triangle. Handles players who finished earlier.
1h
Blocking rule checker
Optional rule: prevents permanently camping home triangle. Detected after every move for applicable players.
2h
Testing
Unit tests — board model
Test all 121 positions loaded. Home/target triangles correct for all player configs. Pixel conversion round-trips.
2h
Critical
Unit tests — move validation
Test valid/invalid step moves, single hops, multi-hop chains, loop detection, wrong-turn errors. Edge cases for blocking rule.
4h
Critical
Unit tests — win condition & apply
Test a complete 2P game end-to-end using move log. Verify state after every move matches expected.
3h
03 Backend API Weeks 2–4

REST API covering authentication, user management, room management, and matchmaking. All inputs validated with Zod. All routes documented. Runs on Express.

Authentication
Passport.js Local strategy (email + password)
bcrypt hash on register. Compare on login. Return JWT access token (15m) + refresh token (7d).
3h
Critical
Google OAuth strategy
Passport Google OAuth2. Create user on first login. Link to existing account if email matches.
2h
JWT middleware
Verify access token on protected routes. Attach req.user. Return 401 on expired/invalid.
1h
Refresh token rotation
Single-use refresh tokens stored in Redis. Issue new pair on refresh. Old token blacklisted immediately.
2h
Guest session endpoint
POST /auth/guest → creates ephemeral user, returns short-lived token. Guest flag prevents ranked access.
1h
Users & Profiles
User CRUD endpoints
GET /users/:username, PATCH /users/me. Enforce username uniqueness. Sanitize display name.
2h
Avatar upload (S3 presigned URL)
Client requests presigned URL → uploads directly to S3 → POSTs URL to API. Validate file type + max 2MB.
2h
Game history + ELO history endpoints
Paginated. Support filters (mode, date range). ELO history returns array of {date, rating} for chart.
2h
Rooms & Lobby
Create room endpoint
POST /rooms. Generate 6-char invite code (no ambiguous chars). Validate settings with Zod. Store in DB.
2h
Critical
List public rooms endpoint
GET /rooms?playerCount=4. Only rooms with status=waiting and open seats. Paginated, max 50/page.
1h
Join room endpoint
POST /rooms/:code/join. Assigns color, returns socket token. Rejects if full or game already started.
2h
Matchmaking
Matchmaking queue (Redis sorted set)
Score = ELO. Dequeue pairs within ±150 ELO window. Expand to ±300 after 60s. Create game on match.
4h
Critical
Queue status polling endpoint
GET /matchmaking/status → estimated wait time based on queue depth. Client polls every 2s.
1h
Games & Replays
Game metadata endpoint
GET /games/:id → returns game settings, players, status, duration.
1h
Move log endpoint (replay)
GET /games/:id/moves → full ordered move list with path arrays for animation replay.
1h
Rate limiting
express-rate-limit: 100 req/min general, 5 req/min on auth routes. Redis-backed for multi-node.
1h
Leaderboard endpoint
GET /leaderboard?mode=multi → top 100 by rating. Cached in Redis, refreshed every 5 min.
1h
04 WebSocket Layer Weeks 3–5

Socket.io server with Redis adapter for multi-node support. All game real-time events flow through here. The server is the sole authority — clients only send intent, the server decides outcome.

Server Setup
Socket.io server + /game namespace
Attach to Express HTTP server. Separate /game namespace. Auth middleware validates JWT on connection.
2h
Critical
Redis adapter (@socket.io/redis-adapter)
Required for multi-node. Events broadcast across all app instances. Test with 2 local server processes.
2h
Critical
Event validation middleware
All incoming socket events validated with Zod before reaching handlers. Emit error on invalid payload.
1h
Room Events
room:join handler
Validate token. Load room from DB. Add socket to Socket.io room. Emit room:state to joiner. Broadcast room:player_joined to others.
2h
Critical
room:leave + disconnect handler
Pre-game: remove player, broadcast. Mid-game: start 60s reconnection window before treating as timeout.
2h
Chat Events
chat:send handler
Validate content (max 200 chars). Profanity filter pass. Persist to DB. Broadcast chat:message to room including spectators.
1h
Game Events
game:move_attempt handler
Validate it's the player's turn. Run game engine validator. On success: apply move, save to Redis + DB, broadcast game:move_confirmed. On fail: emit game:move_rejected to mover only.
4h
Critical
game:request_preview handler
Run getValidDestinations from engine. Emit game:valid_destinations back to requesting socket only.
1h
Turn timer logic
Start setTimeout on turn start. Store timerEndsAt in Redis. On timeout: pick random valid move, apply, emit game:timeout_move. Three timeouts → auto-resign.
4h
Critical
Win condition + game over flow
After each move, run checkWin. On finish: record place, continue game for remaining players. When all done: run ELO calc, persist, emit game:over.
3h
game:resign handler
Mark player as resigned with current finish position. Continue game for others. Recalculate ELO if game ends.
1h
Reconnection handler
On reconnect within 60s: re-attach socket to room, emit full game:start with isReconnect:true. Resume paused timer.
3h
Spectator Events
spectator:join handler
Join socket room. Emit full game state. Flag socket as spectator (cannot send moves). Broadcast updated spectator count.
1h

06 Board Renderer Weeks 4–6

HTML5 Canvas rendering of the game board. This is the most complex UI component — it needs to feel smooth, beautiful, and respond to clicks accurately. The coordinate math from the game engine feeds directly into the renderer.

Canvas Foundation
Canvas component + resize handler
React ref to canvas element. Listen to window resize. Recalculate hex size to fill available space. DPI scaling for retina screens (devicePixelRatio).
3h
Critical
Render loop (requestAnimationFrame)
60fps render loop. Only re-render when state has changed (dirty flag). Clear → draw board → draw marbles → draw overlays.
2h
Critical
Board hole rendering
Draw all 121 holes as circles. Home triangle holes subtly tinted with player color at 15% opacity. Empty holes: grey.
2h
Critical
Marble rendering
Radial gradient circle (white highlight at 35% 30% → player color → dark edge). Looks 3D. Crisp at all sizes.
2h
Interaction
Click/tap detection
Canvas mouse/touch events → pixel → hex coordinate. Determine if a marble or hole was clicked. Hit-test radius slightly larger than visual marble for forgiveness.
2h
Critical
Marble selection state
Click own marble → select it, emit game:request_preview. Click another own marble → switch selection. Click empty → deselect.
2h
Valid destination overlay
Pulsing dot on each valid destination hole. Animate radius 3→5→3px at 1s period via rAF. Only visible for current player's selected marble.
2h
Move submission on destination click
If destination is in valid set: emit game:move_attempt. Optimistically animate immediately, reverse on game:move_rejected.
2h
Animation
Step move animation
Marble moves from origin to destination over 200ms. Easing: ease-out. Board continues rendering other elements during animation.
3h
Critical
Hop chain animation
Animate marble sequentially through each waypoint in path array. 180ms per hop. Brief pause (50ms) at each landing before next hop.
3h
Critical
Selection glow ring animation
Pulsing ring around selected marble (radius grows and fades). Drawn in player color.
1h
Last-move flash
After a move completes, the origin and destination holes briefly flash (50% white overlay, fade over 600ms). Works for opponent moves too.
1h
Input blocking during animation
Disable marble selection and moves while any animation is playing. Queue incoming move_confirmed events if local animation hasn't finished.
2h
Polish
Board background + star outline
Subtle star-of-david polygon outline behind holes. Color tinted home zones. Looks good at all sizes.
2h
Touch support
Touch events mirror mouse logic. Prevent default to stop scroll-on-drag interfering with marble selection. Works on iOS Safari + Android Chrome.
2h
